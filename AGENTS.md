# Repository Guidelines

## Project Structure & Module Organization

- Packages live under `packages/`, split by language: `packages/<pkg>/ts`, `packages/<pkg>/rust`, `packages/<pkg>/python`.
- Source roots: TypeScript `packages/<pkg>/ts/src`, Rust `packages/<pkg>/rust/src`, Python `packages/<pkg>/python/src` (module name `pq_<pkg>`).
- Tests are colocated per package (e.g., `packages/<pkg>/ts/tests`, `packages/<pkg>/python/tests`).
- Shared scripts live in `scripts/` (for example, `scripts/version.ts`).

## Build, Test, and Development Commands

- `npm run build` / `npm test` / `npm run lint` / `npm run typecheck`: run across all TypeScript workspaces when scripts exist.
- `cargo build` / `cargo test`: build and test the Rust workspace.
- `cargo fmt --check` / `cargo clippy --all-targets --all-features -- -D warnings`: Rust formatting and linting (warnings are errors).
- Python per package (from `packages/<pkg>/python`): `pip install -e .`, `pytest tests -v`, `ruff check .`, `python -m build`.
- Version bumping: `bun run scripts/version <package>/<language> <major|minor|patch>` (creates commit + tag).

## Coding Style & Naming Conventions

- TypeScript: ES2022 target, ESNext modules, strict mode; formatted via Biome (VS Code settings).
- Rust: edition 2021; keep Clippy clean.
- Python: 3.8+; lint with Ruff.
- Package naming: directories use `pq-<name>`; Python module uses `pq_<name>`.

## Testing Guidelines

- Prefer package-local tests and run them from the package directory.
- Use `npm test` or `bun test` for TS packages, `cargo test` for Rust, and `pytest tests -v` for Python.
- Keep tests close to the implementation and name them consistently with the language’s conventions.

## Commit & Pull Request Guidelines

- Commit messages use short, imperative summaries (e.g., “Add …”, “Fix …”).
- Version bumps use `chore(<package>): bump <language> version to <version>` (generated by the version script).
- PRs should include a clear summary, test notes (commands + results), and links to related issues/tickets when available.

## Versioning & Publishing

- Tags follow `<package>/<language>@<version>`; pushing tags triggers publishing workflows.
- Manual publish paths: `packages/<pkg>/ts` (npm), `packages/<pkg>/rust` (crates.io), `packages/<pkg>/python` (PyPI).
